VP运维工具 v1.0 — 服务器端部署说明
=========================================

【概述】
服务器端仅用于版本更新发布，通过 SMB Windows 共享提供更新文件。
客户端通过读取此共享中的 version.json 判断是否有新版本。

=========================================
一、搭建 SMB 共享
=========================================

1. 在服务器上创建文件夹，如 D:\AppUpdate\
2. 将本文件夹下所有内容复制到 D:\AppUpdate\
3. 右键 D:\AppUpdate → 属性 → 共享
   - 共享给 "Everyone"，权限设为"读取"
   - 记下共享路径，如 \\192.168.1.100\AppUpdate

4. 确保客户机能访问此共享：
   在客户机上 Win+R → 输入 \\192.168.1.100\AppUpdate → 能打开即可

=========================================
二、文件结构
=========================================

\\服务器\AppUpdate\
├── version.json                ← 版本元数据（发布新版时修改此文件）
│
├── 1.0.0\                      ← 当前版本
│   ├── MoveImageForm.exe
│   ├── MoveImageForm.exe.config
│   ├── Renci.SshNet.dll
│   ├── Microsoft.Bcl.AsyncInterfaces.dll
│   ├── System.Runtime.CompilerServices.Unsafe.dll
│   └── System.Threading.Tasks.Extensions.dll
│
└── 1.0.1\                      ← 未来新版本（示例，发布时替换为新版 exe）
    └── ... (同上)

=========================================
三、发布新版本操作
=========================================

1. 编译好新版 MoveImageForm.exe

2. 在服务器 D:\AppUpdate\ 下新建文件夹，用新版本号命名（如 1.0.1）

3. 将新版 MoveImageForm.exe 及所有 DLL 文件复制到新文件夹

4. 修改 version.json：
   - 将 "latest" 改为 "1.0.1"
   - 在 "versions" 中增加 1.0.1 条目：

   {
       "latest": "1.0.1",
       "versions": {
           "1.0.0": {
               "date": "2026-07-28",
               "note": "初始版本"
           },
           "1.0.1": {
               "date": "2026-07-30",
               "note": "修复了xxx，新增了xxx功能"
           }
       }
   }

5. 完成！客户机下次启动 Launcher 或点击"立即检查"时会自动发现新版本。

=========================================
四、注意事项
=========================================

- 版本号格式：x.y.z（如 1.0.1），每次递增
- 每个版本文件夹内必须有 MoveImageForm.exe
- version.json 的 latest 字段必须和实际存在的版本文件夹名一致
- SMB 共享权限设为"读取"即可，不需要写入权限
- 如果客户机无法访问 SMB 共享，检查防火墙是否阻止了 445 端口
